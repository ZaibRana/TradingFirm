## Spec

Part 3.3 turns the cached 3.2 core-quotes envelope into a market health score. Six pure monitors (`vix`, `spy_trend`, `breadth`, `sector_rotation`, `volume`, `cross_asset`) each return exactly `{score, raw, detail, stale}`. `scoring/health_calculator.py` combines them with Part 5's weights, and `scoring/regime_classifier.py` maps the score to HEALTHY ≥ 70 / CAUTIOUS 40–69 / DANGER 20–39 / CRITICAL < 20. Every pairing of tickers is aligned **on date, never by position**. A same-day bar still inside the session is **partial**. A refused or cooling-down source is answered from a last-known body with `stale: true` and is never an error.

It must **not**:
- pair two tickers' bars by array index
- raise out of a monitor, or out of `compute_health`, because a source refused, cooled down, came back degraded or has too little history
- read `^VIX` volume
- count a missing monitor as a score of 0
- write to Postgres, publish on `tf:risk:health`, or add an endpoint, a scheduler or a lifespan change (all 3.4)
- make a new external request of any kind, or change the 3.2 download, its cache TTLs or its cooldowns
- call yfinance, FRED, Postgres or Redis from a test
- touch the prod container, the prod image tag or the prod database

Acceptance:
- every failure-branch row below has a passing test in `tf-risk-shield-dev`, and the 122 existing tests still pass
- the table-driven monitor tests carry the Part 5 example values, `VIX 45 → 5` among them
- no live run: 3.3 computes on cached data only
- prod is untouched

## Decisions the plan row leaves open

### 1. Date alignment (carry-forward, first)

The 3.2 live canary returned different date arrays per ticker in one download: the ETFs ended on the prior session (251 rows), while `^VIX` (254) and the futures (252) carried today's bar.

- **One function pairs tickers:** `monitors/series.py: align(view, tickers)`. It inner-joins the requested tickers on the `date` string and returns `{dates, close: {T: []}, low: {T: []}, volume: {T: []}}` for dates **present in every one of them**. Nothing else in 3.3 indexes two tickers' arrays together. Dates absent from any ticker are dropped and counted in the monitor's `raw.droppedDates`.
- **A partial bar is decided by clock, from the download time, never the read time.** A bar is partial iff its date equals the Eastern date of the envelope's `asOf` **and** that `asOf` is before **16:15 ET**. VIX settles at 16:15, which is later than the ETF close. Time comes from `zoneinfo.ZoneInfo("America/New_York")`, as data-engine does. A body downloaded at 15:58 ET still holds a partial bar when it is read at 16:03.
  - **Early-close days** stay partial until 16:15, which is conservative. Holidays need no rule because no bar is dated on one. `exchange_calendars` stays in 3.4.
- **`complete_bars(series, as_of)`** drops a trailing partial bar. `align()` applies it per ticker, each against the `asOf` of the body that ticker came from (decision 2 can merge two bodies).
- **Only `vix` reads a partial bar.** It uses the latest bar as the level (the freshest reading) and sets `raw.partial: true`. Every other monitor uses complete bars only, so an early-session volume bar can never read as "quiet".
- **A series whose dates are not strictly ascending** (duplicate or unsorted) makes that ticker unusable. The monitor scores `null`, the problem is logged at WARNING and named in `detail`. It fails closed because a duplicate date would silently double-weight a day.
- **Unused in 3.3:** `ES=F NQ=F CL=F GC=F`. They are 3.4's night mode.

### 2. Last-known body: option **(b), in the fetcher**

- **On every full answer** (`reason: null`), `get_core_quotes`'s `fetch()` also writes the body to **`tf:risk:cache:quotes_last`**, TTL **86400**. The key is built by `risk_key(KIND_QUOTES_LAST)` with the new kind `"quotes_last"`, so it goes through the one key builder. A degraded body (`partial` / `empty`) is never written there.
- **`quotes.get_quotes_view(r, memory, *, now)`** is the only thing monitors read. Stale is decided here, in one place, not six. It returns a view `{asOf, source, reason, tickers: {T: {…series, asOf, stale}}, staleTickers}`:

  | what `get_core_quotes` did | view |
  |---|---|
  | full answer (fresh or cache hit) | that body; `source: "fresh"` / `"cached"`, `reason: null`, nothing stale |
  | `partial` | fresh tickers from the body; each missing ticker filled from last-known and marked stale; `reason: "partial"` |
  | `empty` | the whole last-known body, all stale, `reason: "empty"` |
  | `QuotesCoolingDown` | the whole last-known body, all stale, `reason: "cooldown"` |
  | `QuotesRateLimited` | the same, `reason: "rate_limited"` |
  | `QuotesError` (unexpected raise, version guard) | the same, `reason: "error"`, logged at **ERROR**: a bug must not hide for 24 h behind a quiet stale flag |
  | any of the above with no last-known (absent, expired, wrong shape, Redis `None` or raising) | no series for the affected tickers, all stale, `source: "none"`; never raises |

- **Why (b) over (a):**
  - one copy of one body, not six copies of overlapping slices
  - the stale rule is written and tested once
  - a partial download can be patched per ticker, which (a) cannot do without every monitor re-deriving which of its tickers went missing
- **Staleness and alignment compose.** A stale ticker's series ends earlier, so `align()` drops the newer dates. A pairing monitor then scores the last day all its tickers share and says so in `stale`.
- **A monitor's `stale`** is `true` iff at least one of its input tickers is in `staleTickers`.
- **Without Redis there is no last-known body** (no process-memory copy, G8/G10). A cooldown then gives `score: null, stale: true`, and still no raise.

### 3. FRED is not a 3.3 input

- **Why:** all six Part 5 monitors are quote-based. `VIXCLS` lags a session and duplicates `^VIX`, and `T10Y2Y` has no Part 5 rule.
- **What 3.3 does not do:** write a FRED last-known key, handle `FredCoolingDown`, or judge FRED freshness by series cadence.
- **Where it goes:** all three move to the first part that reads FRED (3.6's macro-brief snapshot). They are recorded as carried in `docs/decisions.md` with the same option (b) shape, so both fetchers end up with one stale mechanism.
- **Recommendation, open for your call:** building the FRED side now would be code with no consumer.

### 4. Monitor contract

- **Keys:** exactly `score`, `raw`, `detail`, `stale`.
  - `score`: `int` in 0–100, or `None` when the monitor cannot score (missing ticker, too little aligned history, unusable series).
  - `raw`: JSON-safe dict, camelCase keys, never NaN or inf.
  - `detail`: one human line, for example `"VIX at 22.4 — elevated uncertainty"`.
  - `stale`: `bool`.
- **Monitors are pure functions of a view:** no I/O, no clock beyond `asOf`, no pandas. They work on plain lists of about 250 floats, so nothing large needs `del` (G8).
- **They live in `monitors/regime.py`,** six functions plus a `MONITORS` registry: name → (function, weight, input tickers).
- **"Above" an EMA means strictly greater**, so equal counts as below (fails closed).
- **`vix` reads `^VIX` directly from the view, never through `align()`**, which would strip the partial bar.
  - Its level is the last bar in the series, partial or not.
  - `prevClose` is the last **complete** bar dated before that one (via `complete_bars`).
  - With one bar there is no `prevClose`: `raw.prevClose` and `raw.changePct` are `null`, there is no spike check and no raise.
- **The other five read only through `align()`.**

| monitor | weight | tickers | bars | bars needed to score |
|---|---|---|---|---|
| `vix` | 25 | `^VIX` | read directly: latest (partial allowed) + previous complete | ≥ 1 (≥ 2 for the spike check) |
| `spy_trend` | 20 | `SPY` | complete | ≥ 200 |
| `breadth` | 20 | `RSP`, `SPY` | aligned, complete | ≥ 20 |
| `sector_rotation` | 15 | `XLK XLY XLF XLU XLP XLV` | aligned, complete | ≥ 6 |
| `volume` | 10 | `SPY`, `QQQ` | aligned, complete | ≥ 21 |
| `cross_asset` | 10 | `TLT GLD UUP SPY` | aligned, complete | ≥ 2 |

### 5. The six scoring rules

Every row states its comparison.

- **Where the operators come from:** where Part 5 states an operator, it is used verbatim. Where it gives a bare range, the range is lower-inclusive. The one exception: a bare range that meets a Part 5 `>` row closes at the top, so the edge still has a row (VIX 40, volume 2.5).
- **Numbers marked new** are not in Part 5. They are accepted as **provisional** and marked so in `docs/decisions.md`, so Phase 5/6 can retune them without a spec correction.

**`vix`** (Part 5 table):

| level | score |
|---|---|
| level < 15 | 95 |
| 15 ≤ level < 20 | 80 |
| 20 ≤ level < 25 | 60 |
| 25 ≤ level < 30 | 40 |
| 30 ≤ level ≤ 40 | 20 |
| level > 40 | 5 |

- **Spike:**

  | condition | adjustment |
  |---|---|
  | latest > prevClose × 1.20 | −15, then floored at 0 |
  | latest ≤ prevClose × 1.20 | none |
  | `prevClose` is `null` (1 bar) | no check |

  The comparison is multiplicative, so there is no float drift at exactly +20%. VIX 45 plus a spike → 0.
- **`raw`:** `{level, prevClose, changePct, date, partial}`.

**`spy_trend`:**
- **EMAs:** 20/50/200 on complete closes, seeded with the first close, α = 2/(span+1), matching data-engine's `ema` (pandas `ewm(adjust=False)`).
- **Lower lows:** `min(low[-10:]) < min(low[-20:-10])`. **New definition.**
- **First match wins:**

  | condition | score |
  |---|---|
  | close ≤ EMA200 and lower lows | 5 |
  | close ≤ EMA20 and close ≤ EMA50 and close ≤ EMA200 | 15 |
  | close ≤ EMA200 and (close > EMA20 or close > EMA50) | **25** (new: Part 5 has no row for a bounce under the 200) |
  | close > EMA20 and close > EMA50 and close > EMA200 | 95 |
  | close ≤ EMA20 and close > EMA50 and close > EMA200 | 70 |
  | close ≤ EMA50 and close > EMA200 | 45 (Part 5 "above 200 EMA only", whatever the 20) |

- **Known limit:** 1y of daily bars leaves about 8% seed weight in EMA200. Accepted, because the alternative is a 2y download, which changes 3.2.
- **`raw`:** `{close, ema20, ema50, ema200, lowerLows, date}`.

**`breadth`** (plan substitute for Part 5's constituent breadth):
- **Ratio:** RSP close / SPY close on the last 20 aligned complete dates.
- **Slope:** least-squares slope × 19 / mean ratio × 100, i.e. the fitted % change across the window.
- **Score:**

  | slope | score |
  |---|---|
  | slopePct > +1.0 | 90 |
  | −1.0 ≤ slopePct ≤ +1.0 | 60 |
  | slopePct < −1.0 | 25 |

  The 90 / 60 / 25 steps are Part 5's A/D steps; **the ±1.0 thresholds are new**.
- **A/D is unavailable, not zero:**
  - `data_engine.scan_results` stores `total_screened` / `total_passed` only, and no data-engine endpoint serves advancers or decliners
  - risk-shield reads no other schema
  - so `raw.adRatio: null`, `detail` says "A/D unavailable", and breadth is the ratio alone
  - recorded in `docs/decisions.md`: the plan row's "when available" is not met
- **`raw`:** `{ratio, slopePct, window: 20, adRatio: null, droppedDates, date}`.

**`sector_rotation`:**
- **Spread:** 5-day return = close[-1] / close[-6] − 1 on 6 aligned complete dates. Spread = mean(XLK, XLY, XLF) − mean(XLU, XLP, XLV), in percentage points.
- **Score:**

  | spread | score |
  |---|---|
  | spreadPct > +1 (Part 5 "offensive outperforming by > 1%") | 90 |
  | −1 ≤ spreadPct ≤ +1 | 65 |
  | −2 ≤ spreadPct < −1 (Part 5 "defensive outperforming by > 1%") | 30 |
  | spreadPct < −2 (Part 5 "by > 2%") | 10 |

- **`raw`:** `{offensivePct, defensivePct, spreadPct, droppedDates, date}`.

**`volume`:**
- **Volume ratio:** (SPY + QQQ volume) on the last aligned complete date ÷ the mean of that sum over the 20 aligned dates before it.
  - A row with a `null` volume (either ticker) is excluded from the mean.
  - A `null` on the last date → `score: null`.
  - **Every row in the 20-date window `null`** → `score: null`, with `detail` naming it ("no volume in the 20-day window"). There is never a division by zero.
- **Red / green:** red = SPY close < previous close; green = SPY close ≥ previous close.
- **Rows are mutually exclusive:**

  | condition | score |
  |---|---|
  | ratio < 1.2 (either colour) | 85 |
  | 1.2 ≤ ratio < 1.8 (either colour) | 60 |
  | red and 1.8 ≤ ratio ≤ 2.5 | 30 |
  | red and ratio > 2.5 | 10 |
  | green and 1.8 ≤ ratio ≤ 2.0 | **60** (new: Part 5 leaves it uncovered) |
  | green and ratio > 2.0 | 80 |

  **Where the edges come from:**
  - `1.8 ≤ ratio ≤ 2.5` on a red day is closed at the top because it meets Part 5's "> 2.5x on red day", so exactly **2.5 red → 30**. It is the same edge rule as VIX 40.
  - `1.2 ≤ ratio < 1.8` and `ratio < 1.2` are Part 5's bare range and `<`, lower-inclusive.
  - `1.8 ≤ ratio ≤ 2.0` green is closed at the top by Part 5's "> 2x on green day".
- **`raw`:** `{ratio, red, date, droppedDates}`.

**`cross_asset`:**
- **1-day % change** on the last 2 aligned complete dates.
  - **The 0.5 band is new.** Part 5 says "flat" without a number.
  - **The > 1.0 is Part 5's**, verbatim.
- **First match wins** (the first two rows can overlap with the third):

  | condition | score |
  |---|---|
  | tltPct ≤ −0.5 and gldPct ≤ −0.5 and uupPct ≤ −0.5 and spyPct ≤ −0.5 | 15 |
  | tltPct ≥ +0.5 and gldPct ≥ +0.5 and uupPct ≥ +0.5 | 25 |
  | tltPct > +1.0 and spyPct ≤ −0.5 | 35 |
  | −0.5 < tltPct < +0.5 and −0.5 < gldPct < +0.5 and −0.5 < uupPct < +0.5 | 80 |
  | none of the above | **65** (new: Part 5 has no mixed row; 65 is sector's neutral) |

- **`raw`:** `{tltPct, gldPct, uupPct, spyPct, date, droppedDates}`.

### 6. Health calculator

- **Weights are integer percents:** `{vix: 25, breadth: 20, spy_trend: 20, sector_rotation: 15, volume: 10, cross_asset: 10}`, summing to 100.
- **Integer arithmetic:** `score = floor((2·Σ sᵢwᵢ + W) / (2W))`, where W = Σ wᵢ over monitors whose score is not `None`. This is round half up with no float drift: 69.5 → 70 → HEALTHY. `health_checks.score` is `INTEGER`.
- **Missing monitors are left out, never counted as 0.** The remaining weights renormalize.
- **Coverage floor W ≥ 70** (**new**), otherwise `score: null, regime: null`. Missing breadth and volume (W = 70) still scores; missing vix and cross_asset (W = 65) does not. This is Part 5's "no single indicator can hold the score" in a checkable form.
- **A monitor that raises** (a bug, not a data state) is caught per monitor. It is logged at ERROR with its name and becomes `{score: None, raw: {}, detail: "monitor error: <ExceptionType>", stale: False}`. The other five continue.
- **`health_from_monitors(results) -> dict`** is pure and returns:
  - `score`, `regime`, `coverage` (W)
  - `stale`: any *contributing* monitor stale
  - `staleMonitors`
  - `monitors`: name → contract + `weight`
- **`compute_health(r, memory, *, now) -> dict`** = `get_quotes_view` → `MONITORS` → `health_from_monitors`, plus `checkedAt` and `inputs: {asOf, source, reason, staleTickers}`. **No caller in 3.3.** On a cache miss it would download through 3.2's guarded path; only 3.4's scheduler will call it. `trend` (improving / declining) needs history and is 3.4.

### 7. Regime classifier

- **`classify(score)`:** `None` → `None`; an `int` (not `bool`) in 0–100 → `HEALTHY` ≥ 70, `CAUTIOUS` ≥ 40, `DANGER` ≥ 20, else `CRITICAL`; anything else → `ValueError`.
- **One vocabulary:** the constants are the strings in `health_checks`' and `macro_briefs`' CHECK constraints.
