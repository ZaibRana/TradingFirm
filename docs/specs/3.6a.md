## Spec

Part 3.6a builds everything the macro brief reads, and the column it will write, but not the brief itself:
- **Schema:** migration `006` adds `brief` and `trigger` to `risk.macro_briefs`.
- **News read route:** data-engine `GET /news/market?hours=24&limit=50`.
- **FRED leftovers from 3.3:** a last-known key in the fetcher, cooldown and refusal served as stale data rather than errors, and freshness judged per series cadence.
- **The inputs document:** `macro_inputs.assemble_inputs()` gathers health, settle, news, calendar and FRED plus a `freshness` block, and `GET /macro/brief/inputs` serves it.
- **Flags:** `MACRO_BRIEF_ENABLED` / `AI_AGENT_URL` plumbing, with the twin override.

It must **not**:
- call ai-agent or any LLM, write a `risk.macro_briefs` row, or add the brief schedule, the regime hook, `POST /macro/brief/generate` or `GET /macro/brief` (all 3.6b)
- compute a health check or download quotes on the inputs path: health comes from `risk.health_checks` rows only
- read the `data_engine` schema from risk-shield (HTTP only), or write anything through data-engine
- change `fred_snapshot`'s walk, 3.2's FRED TTLs, cooldowns or key conditions, 3.4's throttle and payload, or 3.5's poller and limits
- turn `MACRO_BRIEF_ENABLED` on anywhere, give the twin a FRED or Finnhub key, or give it a routable ai-agent URL
- call FRED, Finnhub or data-engine from a test
- touch a prod container, image tag or database

Acceptance:

## Decisions

### 1. Migration `006_macro_brief_output.sql`

```sql
ALTER TABLE risk.macro_briefs ADD COLUMN IF NOT EXISTS brief JSONB NOT NULL
    CHECK (jsonb_typeof(brief) = 'object');
ALTER TABLE risk.macro_briefs ADD COLUMN IF NOT EXISTS trigger TEXT NOT NULL
    CHECK (trigger IN ('slot', 'regime_change', 'critical', 'manual'));
```

- **Re-runnable:** a rerun skips each `ADD COLUMN` along with its inline CHECK. There is no seed and no `INSERT`.
- **`NOT NULL` with no default:**
  - `ADD COLUMN … NOT NULL` fails on a table that already has rows. Both tables hold 0 rows today, and nothing writes one before 3.6b.
  - The pre-go list re-checks `count(*) = 0` on prod.
  - A default would hide a writer that forgot the field.
- **Bounded and `allow_nan=False`:** enforced in 3.6b's writer, like `inputs`. The DB only checks that `brief` is an object.
- **Dev:** `./scripts/dev-db.sh` applies it. Proof is a rerun no-op, a direct re-execution of the file, and `\d risk.macro_briefs`.

### 2. data-engine `GET /news/market`

- **Query:** `hours` int 1–168, default 24; `limit` int 1–100, default 50. Anything else is a 422.
- **SQL** (new `db.get_market_news(pool, since, limit)`): `WHERE ticker = $1 AND published_at >= $2 ORDER BY published_at DESC LIMIT $3`, with `$1 = MARKET_TICKER`. The existing `news_items_ticker_published_idx` covers it.
- **Body:** a JSON list, newest first, `[{publishedAt, source, title, summary, url}]` (camelCase, aware ISO). No rows → 200 `[]`, never a 404.
- **Errors:** no pool, `DB_ERRORS` or `TimeoutError` → 503 `database unavailable`. Postgres only: no cache, no provider, no write.
- **Bounds shared across services** (3.5's lesson): risk-shield sends `hours=24&limit=50`. data-engine pins its bounds as `NEWS_MARKET_MAX_HOURS = 168` / `NEWS_MARKET_MAX_LIMIT = 100`, and risk-shield keeps a copy.
  - Pin tests on both sides: `test_news_market_bounds_pinned_for_risk_shield` and `test_inputs_news_request_within_route_bounds`.
  - A drift would mean a 422 on every brief.

### 3. FRED last-known (the 3.3 carry, option (b), in the fetcher)

- **Key:** `tf:risk:cache:fred_last:{SID}` (`KIND_FRED_LAST`), TTL **604,800 s (7 days)**, provisional.
  - **Written:** inside `get_series`' `fetch()`, when a full envelope (`reason: null`) was built and before `cached_json` writes the main key. The same place 3.3 writes `quotes_last`.
  - **Never written** for `empty` or for a raise.
  - **A `SET` raise:** WARNING, and the body is still returned.
- **Why 7 days, not 24 h:** freshness is judged on the observation dates (decision 4), never on the last-known key's age, so a long TTL can't hide staleness. A 24 h TTL would erase a monthly series after one bad day.
- **`get_fred_view(r, memory, client, *, now)`** runs `fred_snapshot` unchanged, then fills every series whose status isn't `ok` from last-known. That covers `cooldown`, `rate_limited`, `not_authorized`, `unconfigured`, `skipped`, `error` and `empty`.
  - **`FredCoolingDown` is stale data, not an error.** Nothing raises out of the view.
  - **No usable last-known** (absent, wrong shape, no Redis): the series has no data and `staleReason: "no_data"`.
  - **No process-memory copy,** as in 3.3 (G8/G10).
- **Per series:** `{status, source: "fresh"|"cache"|"last_known"|"none", stale, staleReason: null|"age"|"last_known"|"no_data", cadence, maxAgeDays, ageDays, latest, monthAgo, yearAgo}`.
  - `latest` is the last observation, as `{date, value}`.
  - `monthAgo` / `yearAgo` are the last observation on or before `latest.date − 30 d` / `− 365 d`. Either is `null` when history is too short.
  - The 800-day arrays never leave the view, so the document stays bounded.

### 5. The inputs document (`services/risk-shield/macro_inputs.py`)

`assemble_inputs(state, fred_client, http, *, now) -> dict`. Every section carries a `status`, and a failing section never stops the others (the 2.4 dossier pattern). 3.6b stores this object unchanged as `inputs` and sends it to ai-agent.

```
{schemaVersion: 1, assembledAt, ready,
 health:   {status: ok|no_checks|unavailable, checkedAt, kind, score, regime, trend, coverage,
            stale, staleMonitors, monitors: {name: {score, weight, stale, detail}}, ageMinutes,
            lastExpectedSlotAt, lastScored?},
 settle:   {present, checkedAt, score},
 news:     {status: ok|empty|unavailable, cause, hours: 24, limit: 50, count, truncated,
            trimmedForSize, items: [{publishedAt, source, title, summary}]},
 calendar: {status: ok|unavailable, from, to, coversThrough, coverageShort, renewalDue, events},
 fred:     {SID: decision 3's per-series object},
 freshness: {...decision 6}}
```

- **Health**
  - **Source:** `db.latest_health_check`. When its score is null, `lastScored` comes from `latest_scored_health_check`, as `/market/health` does.
  - **No checks:** `no_checks`. **No pool or `DB_FAILURES`:** `unavailable`.
- **`lastExpectedSlotAt`** comes from a new `scheduler.last_slot_before(now)`: the latest XNYS slot (market or settle) starting at or before `now − 300 s`.
  - The 300 s is one slot of grace, since a check takes ~5 s cold.
  - `healthStale` is true when there is no row, or the row's `checkedAt < lastExpectedSlotAt`.
  - **At 07:30 ET** yesterday's 16:20 settle is the expected row, so a present settle reads fresh. That is how "07:30 runs with whatever exists" shows up.
  - **The age is never hidden by the fresh verdict (amendment B):** `health.ageMinutes` is carried into `freshness.healthAgeMinutes` as-is. At 07:30 it is ~670. The test asserts `healthAgeMinutes > 600` beside `healthStale: false`, so a later "fix" to the verdict can't be made without seeing the age is still exposed.
  - On the twin, with the scheduler off, it reads stale, which is correct.
- **Settle:** `db.settle_base(pool, now)` gives the latest scored settle, reported as present or absent.
- **`ready`** means the pool answered and a scored row exists (the latest or `lastScored`). It is 3.6b's precondition to spend an LLM call; 3.6a only reports it.
- **News**
  - **Request:** one `GET {data_engine_url}/news/market?hours=24&limit=50`, 10 s hard bound, no retries, no redirects followed.
  - **200 with a list:** `ok`. An empty list is `empty`.
  - **Failures:** non-200, a transport error or a timeout is `unavailable` with `cause`, logged as WARNING. A body that isn't a list, or an item missing a field, is `unavailable` with `cause: "bad body"` and one ERROR per distinct problem: it's our own route, so it means contract drift.
  - **Items:** `title` and `summary` cut to 300 chars (counted in `truncated`). `url` is left out: tokens and size. `publishedAt` + `source` + `title` identify an item for the journal.
- **Calendar:** `econ_calendar.window(cal, now, 7)`, plus `renewalDue` = `coverage_short(cal, et_today)`. `CalendarUnavailable` gives `unavailable`.
- **FRED:** `get_fred_view` under `state.inputs_lock` (decision 7).
- **Bounded:** serialized compact with `allow_nan=False` (a NaN raises).
  - Over `INPUTS_MAX_BYTES = 64_000` (UTF-8), the oldest news items are dropped one at a time, counted in `trimmedForSize`.
  - Still over with no news left: `InputsTooLarge`. That's unreachable with these caps, so it's a bug and a 500.
  - The worst case is 50 items × ~2.8 KB of 4-byte text, so the trim is real code, not decoration.

### 6. `freshness`: the flags the brief quotes

`{healthStatus, healthStale, healthMonitorsStale, healthAgeMinutes, settlePresent, newsStatus, newsPollStale, lastNewsPollAt, newsLastError, calendarStatus, calendarWindowShort, calendarRenewalDue, fredStaleSeries: [SID…], anyStale}`

- **The three news-poll keys** are `news_poller.stale_view(state, now)`, unchanged. `null` means the poller is off (the twin, and any process without it), never "unknown".
- **`anyStale`** is true if any of these holds:
  - `healthStatus != ok`, `healthStale`, or `healthMonitorsStale`
  - `settlePresent` false
  - `newsStatus != ok` (an empty 24 h counts: an empty result is a failure)
  - `newsPollStale is True`
  - `calendarStatus != ok` or `calendarWindowShort`
  - `fredStaleSeries` non-empty
- **Excluded from `anyStale`:**
  - `calendarRenewalDue` is a maintenance flag, and the inputs are still correct.
  - `newsPollStale: null` isn't evidence of anything.

### 7. `GET /macro/brief/inputs`

- **Response:** always 200 with the document plus `cached`; each section says why it's degraded. It works regardless of `MACRO_BRIEF_ENABLED`.
- **60 s reuse (amendment A):** the lock stops a burst, but not a slow loop of calls.
  - `app.state.inputs_last = (monotonic time, document)`, checked under the lock.
  - A call within `INPUTS_REUSE_SECONDS = 60` of the last successful assembly returns that document with `cached: true`. `assembledAt` shows its real age.
  - Otherwise it assembles again (Postgres, data-engine; FRED through its 6 h cache) and returns `cached: false`.
  - **`cached` is added on the way out, never part of `assemble_inputs()`'s result**, so 3.6b stores no `cached` field (1.7's rule).
  - **A raise during assembly caches nothing,** so the next call assembles.
  - The clock is `time.monotonic`, patchable. Process memory only: a restart forgets it, and 3.6b's generator calls `assemble_inputs()` directly, never this reuse.
- **One assembly at a time:**
  - `app.state.inputs_lock`, an `asyncio.Lock` created in lifespan (the per-loop lesson from 3.2).
  - A burst of calls on a cold FRED cache makes one 8-request walk, not N.
- **Clients:**
  - `app.state.fred_client` (`FredClient`, no HTTP at construction) and `app.state.inputs_http` (`httpx.AsyncClient`, `follow_redirects=False`) are created in lifespan whatever the flags.
  - They are closed at shutdown, after the tasks in `running` stop and before the pool and Redis close.
- **FRED cost:** the first prod FRED reader. At most 8 requests per 6 h per series-cache expiry, under the limiter and the cooldowns. No auth, and port 8003 is published: accepted and carried to the going-public checklist, like `/news/ingest`.
- **Discovery:** `/` lists the route. `/health` adds `macroBriefEnabled`.
